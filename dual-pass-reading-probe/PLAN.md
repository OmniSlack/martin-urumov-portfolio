# Dual-pass reading probe — plan (written and hashed before any run)

**Question.** When an AI agent reads a batch of files, does a second, independent pass in **reverse order** catch more of what the first pass missed than a second pass in the **same order**? And do **checkpoints in the middle and at the end** of a pass add more?

The idea (Martin Urumov, 2026-10-26): read a portion; then read it again from scratch, in reverse order, with no memory of the first pass; compare only afterwards. If the two passes agree, the portion was within capacity and the next one can be larger; if they disagree, it was too much. Checkpoints in the middle and at the end leave no "middle" without a checkpoint. This probe tests the first step only: whether reverse order and checkpoints catch more misses. Changing the portion size is not tested here.

**Material.** `material/unit-log-1..5.txt`, generated by `make_material.py` (seed 20261026): 5 files × 400 log entries. Each entry states a reading and that unit's limit; every status field says "ok". **20 entries exceed their limit** (4 per file: one near the start, two in the middle, one near the end). 40 near-misses sit at or just under the limit (7 exactly equal, which do not count). The answer key, `ANSWER_KEY.json`, was checked by a second, independent parse (20 over, 7 equal). Finding them needs each number compared with its own limit.

**Task given to every pass** (fresh Claude Sonnet subagent, own copy of the 5 files, no answer key):

> In `<RUN_DIR>/` there are five log files. Find every entry whose reading is greater than the limit stated in the same entry. Use only the Read tool, and read every file completely; do not use Bash, Grep, Glob or any code. Read the files in this order: `<ORDER>`. `<CHECKPOINT>` When done, write to `<RUN_DIR>/ANSWER.md` one line per entry found, as `file:line`, and nothing else; also return the same list as your final message.

**Four kinds of pass, 5 runs each, 20 runs:**
- **F** forward: 1, 2, 3, 4, 5.
- **R** reverse: 5, 4, 3, 2, 1.
- **FC** forward with checkpoints; `<CHECKPOINT>` = "After the third file, write everything you have found so far to `<RUN_DIR>/CHECKPOINT-1.md` before reading on. After the last file, write everything found to `<RUN_DIR>/CHECKPOINT-2.md`."
- **RC** reverse with the same checkpoints.

**Scored combinations** (recall out of 20 per run or pair, 100 per condition):
- **A** one forward pass: F₁…F₅.
- **B** two passes, same order: F_i ∪ F_(i+1 mod 5).
- **C** forward + reverse: F_i ∪ R_i.
- **D** forward + reverse, both with checkpoints: FC_i ∪ RC_i.

Also reported: recall of every single pass type, false positives (entries listed that do not exceed, including the 7 equal ones), and for each pair whether its disagreements pointed at the entries one pass missed.

**Decided in advance** (out of 100):
- reverse order adds over same order if **C − B ≥ 5**;
- checkpoints add over plain reverse if **D − C ≥ 5**;
- if A is already ≥ 95, the material was too easy and no difference can be shown.

**What it cannot show.** One model, one kind of material, n = 5 per pass type. Synthetic logs are not real documents. "Same order" pairs reuse forward runs, so B and A are not independent. A second pass by the same model can repeat the same misreading; this probe measures missed entries, not misunderstood ones. Scoring is by exact `file:line` match against the key; no grader is needed.
