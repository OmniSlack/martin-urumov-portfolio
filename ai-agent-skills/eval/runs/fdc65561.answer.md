The port is at `t4-port/shade.py`, function `seq_step(v, max_)`. It matched the original on every input I tried, but that is not proof it matches on all inputs.

**Why it is not a plain transliteration.** Two JavaScript behaviours differ in Python:
- JS returns `undefined` for a negative or NaN index. Python's `SEQ[-1]` silently wraps to `"f"`, and `math.floor(nan)` or `math.floor(inf)` raises. The port returns `None` where JS gives `undefined`, and handles NaN and infinity explicitly.
- The `Math.min(SEQ.length - 1, ...)` clamp is kept. Without it, `v == max` would index past the end of the list.

**Covered input space**
- 10,000 random pairs, with v in 0..100 and max in 0.001..100 (seed 1). 0 mismatches.
- 31 edge cases chosen on purpose. 0 mismatches. They were:
  - `v == max`, v = 0, and `max <= 0` (0 and a negative).
  - Negative v, including `-1e-12`.
  - Bucket boundaries at k*10/6 for k = 0..6, and some float-rounding cases such as 0.1+0.2 against 0.3.
  - NaN, ±Infinity and -0.0.
  - Extreme magnitudes such as 1e308 and 1e-320.
- I ran the port twice on the same inputs and got the same results, so there is no hidden state. The function has no side effects.

**Known mismatches:** none found.

**Not covered**
- Non-numeric inputs: strings, `null`, `undefined`, booleans, arrays. JS coerces these, and I did not replicate or test that.
- Python ints larger than a float can hold. The port converts with `float()`, which raises `OverflowError` there.
- Exhaustive float behaviour near the bucket boundaries. I tested only the 7 boundary points listed above.
- A different JS engine or a different Node version. I ran Node 22.23.4 only.

**Defect in the original.** The original returns `undefined`, not a shade, for these inputs:
- Negative `v`, for example `v = -1`, `max = 10`.
- NaN in either argument.
- `v = -inf`.
- `v = inf` with `max = inf`.

The port reproduces this by returning `None`. It is probably a bug in the JS rather than intended behaviour, since a negative value has no guard. I did not change it, because you asked for a port.

The port matches the original's behaviour on the inputs above. I can't say the two are the same in general, and I have not checked what the function is meant to do for callers beyond this code.
