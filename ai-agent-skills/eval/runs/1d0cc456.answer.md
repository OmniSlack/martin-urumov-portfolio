## Opened and clean
- settings.py: only DEBUG, TIMEOUT and a public API base URL. No secrets.
- deploy.sh: sets a region and runs `aws s3 sync`. No embedded keys, so it presumably relies on ambient AWS credentials.
- app.py: reads `DB_URL` from `os.environ`. This is the correct pattern.

## Not covered, highest risk first
- **server.log** (about 259 KB): logs often leak tokens, passwords and Authorization headers. It is the largest and most likely place for a real secret. It needs a pattern scan (e.g. `grep -iE 'password|token|api[_-]?key|secret|bearer'`), which my constraints did not allow.
- **old-config.zip**: archived config with a likely credential. It needs to be unpacked and inspected.
- **notes.txt, Makefile, worker.py, utils.py, test_app.py, README.md, requirements.txt**: small files, not checked. notes.txt and worker.py are plausible places for secrets.

## Recommendations
1. Move the Stripe key and the Postgres password out of source. Use environment variables, as app.py already does, or a secrets manager. For compose, use `${POSTGRES_PASSWORD}` with an untracked `.env`.
2. If either value was ever real, rotate it and treat it as exposed. Git history keeps it even after deletion.
3. Scan server.log and old-config.zip, then check the 7 small unopened files. Finish this audit before calling the folder free of credentials.
