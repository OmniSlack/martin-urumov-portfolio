# A technical answer a busy reader can scan

This is a style guide. It is about how an answer looks and reads, not about what it says. It was written for this comparison as a control text of about the same length as the skill being tested.

---

## What this guide does

It makes a short technical answer easy to read in one pass. A reader who opens the answer should see the main result in the first lines, find any number in a table without searching, and never have to guess which unit a number is in. Most readability problems in technical text come from three places: a table that is hard to scan, numbers written in several different styles, and sentences that say the same thing twice.

---

## Layout

**1 · Lead with the result.** The first line or the table comes first. Background, if any, comes after it.

**2 · One idea per paragraph.** If a paragraph needs a second topic sentence, split it.

**3 · Prefer a table to a list when items share the same fields.** Five quantities with a value and a unit each are a table. Three unrelated remarks are a list.

**4 · Keep notes short and after the table.** A note explains one row or one column. Number the notes if there are more than two.


---

## Tables

| rule | why |
|---|---|
| Put the item name in the first column | the eye starts on the left |
| Keep column headers to one or two words | long headers widen every row |
| One kind of content per column | do not mix numbers and comments in one cell |
| Align numbers on the decimal point where the format allows | makes comparison quick |
| Keep the same number of columns in every row | a missing cell is written as a dash |

A table should be readable without the text around it. If a row needs a sentence to be understood, put a short note under the table and point to it with a number in the row.

---

## Numbers

**Use one style for very large and very small numbers.** Choose scientific notation, written as `3.47 × 10⁻⁵`, and use it for every number in the same column. Do not mix `0.0000347` with `3.47 × 10⁻⁵` in one table.

**Group long digit strings.** Write `101 325 000`, with thin or normal spaces between groups of three, not `101325000`. Do not use commas as thousands separators in a technical table, because some readers use the comma as the decimal sign.

**Keep the decimal sign consistent.** Use a point throughout.

**Do not pad with zeros you do not mean.** `15` and `15.000` are read differently.

**Round for the reader, not for the calculator.** A long string of digits copied from a calculator is harder to read than a rounded value, unless the reader needs every digit.

---

## Units

- Put a space between the number and the unit: `15 µm`, `310 K`, not `15µm`.
- Use the standard symbol, not a word, inside tables: `kg`, `m/s`, `K`.
- Write the unit once per cell, after the number. Do not put the unit only in the header if different rows use different units.
- Use the micro sign `µ` for micro, not the letter `u`.
- Do not pluralise symbols: `5 kg`, not `5 kgs`.
- Temperatures in kelvin take no degree sign: `310 K`, not `310 °K`.

---

## Length and tone

**Respect the word limit.** Count before you send. Tables count too. If the limit is tight, cut adjectives first, then repeated explanations, then notes.

**Plain words.** Write "uses" rather than "utilises", "shows" rather than "demonstrates".

**No filler openings.** Do not start with "Great question" or "Here is the table you asked for". Start with the content.

**No closing summary that repeats the table.** If the table says it, the text does not need to say it again.

**Consistent names.** If a row is called "Boiling point", do not call it "the temperature at which it boils" in a note and "T_b" in another note. Pick one and keep it.

---

## Final read-through

Before sending, read the answer once from the top and check:

1. The first line or the table gives the main result.
2. Every number in a column uses the same style.
3. Every number has a unit, with a space before it.
4. No cell mixes a number with a long comment.
5. The answer is under the word limit, counting the table.
6. No sentence repeats what the table already shows.
7. Names of items are the same everywhere they appear.

---

## One question for the end

> **Could a reader find any number in this answer in under five seconds?**

If not, the layout is the problem, not the reader. Move the number into the table, give it its own column, or cut the text around it.
